# 02 · 阶段化双态世界书：随剧情推进自动载入角色状态

> 命题：**「卡不动、状态走世界书」**——角色卡文件保持原样不编辑，剧情推进产生的状态翻转（身份交底、伏笔兑现）全部由世界书条目对**聊天记录中的事件词**做扫描响应来完成：事件词落进扫描窗 → 后态条目激活、前态条目被压制，角色行为基线随之切换。卡是静态的，状态是动态的。
> 本文用合成示例（角色「夜鸦」/真名「星织」/信物之约）讲机制；实战版含正典逐字引文与 record_id 回链，留在内部工作区。配套机器可读示例见 `examples/staged_entries_example.json`。

---

## 〇、总设计：双态对的结构模板

每对双态 = **前态（默认在位）+ 后态（翻转后）**，共用一个互斥组（group + group_override=true），靠三重机制保证「同一时刻至多一态在位」：

| 机制 | 前态 | 后态 | 依据（ST World Info 语义） |
|---|---|---|---|
| ① NOT_ANY 副键压制 | `secondary_keys`＝翻转事件词表，`selectiveLogic=2`（NOT_ANY：任一副键出现在扫描窗即不激活） | 无副键，`selectiveLogic=0` | NOT_ANY=2（源码枚举实锤） |
| ② order 压制 | order 小（更靠前、权重弱） | order 大（更靠后、权重强），**后态=前态+2** | order 大者靠近上下文末尾 |
| ③ group 互斥 | `group=状态组名`，`group_override=true` | 同组同配置 | 组内同时触发只留一条；override=true 时改选 order 最高者（确定性） |

**翻转语义**：后态 keys = 翻转事件词（取自交底/兑现场景的**第一人称陈述句式** + 用户可能说出的变体）。事件词一旦落进扫描窗（scan_depth 内，角色台词或用户消息都算），后态激活；同时前态因 NOT_ANY 命中同一词表被压制。**后态一律 sticky=999**：翻转后即使事件词滚出扫描窗，状态也持续约千条消息（跳过概率检），这是「单向状态门」的持续力来源。

**参数基线（六条通用）**：
1. `position=after_char`（与规则条目一致）；
2. `probability=100/useProbability=true`（状态门不允许概率抖动）；
3. `prevent_recursion=true`（条目内容内嵌引文含人名/事件词，防递归连锁）；
4. `scan_depth=null`（继承全局值）；
5. `constant=false`（前态必须可被压制，后态靠 sticky 而非蓝灯——蓝灯会失去「翻转前不存在」的性质）；
6. `enabled=true`。

**order 带位**：双态组整体放在既有条目 order 区间的下沿（如既有 50-100，则组用 38-48），作「状态层」不挤占既有指纹/设定层的语义位；组内 +2 差值留出未来插入中间态（如「交底进行中」）的余量。

## 一、身份双态示例（合成）

角色有两个名字：化名「夜鸦」（默认对外），真名「星织」（剧情中段向同伴交底）。翻转词全部取自**交底场景的自然说法**与用户变体。

### 前态「化名态」（id 100，默认在位）

> 【身份状态·化名态｜默认在位】对外只报代号「夜鸦」；真名与来历＝红线：绝口不提；被戳时神色不变、装傻岔开；问名可以，报名免谈。禁止：报真名；承认过去身份；当场动摇。

### 后态「交底态」（id 101，翻转后）

> 【身份状态·交底后】真名「星织」已亲口交底：红线解除——可自报真名、可谈来历，不再装傻；称呼用「星织」。仍守：不对新面孔倾倒身世；不拿交底当谈资。

### 参数表

| 参数 | id 100 化名态（前） | id 101 交底态（后） |
|---|---|---|
| keys（主键） | 名字／叫什么／怎么称呼／称呼／代号／化名／本名 | **=翻转词表**（下） |
| keysecondary（副键） | **＝翻转词表，selectiveLogic=2（NOT_ANY）**：我真正的名字／真正的名字／我的真名／真名是星织／我是星织／以前的假名 | 无 |
| order | 46 | **48**（压前态） |
| position | after_char | after_char |
| sticky | null | **999** |
| group / override / weight | demo-stage-identity / **true** / 100 | 同左 |
| constant / selective | false / **true**（副键机制启用） | false / false |
| 库归属判定 | **专属库**（角色本人身份态） | **专属库** |

### 翻转词表选型依据

翻转键全部取**第一人称陈述句式**（交底场景角色会怎么说 + 用户替角色说出来会怎么说）：①「我真正的名字」＝交底起手式；②「真正的名字」＝第三人称变体；③「我的真名」；④「真名是星织」；⑤「我是星织」＝自报式；⑥「以前的假名」＝追认式。

**刻意排除的词**：「真名」单独不作翻转键（见失效模式 F3）；角色名「星织」「夜鸦」单独绝不可作键（见 F2 前缀陷阱）；真名单字变体不作键（交底前被局外人提及属边缘剧情，防误翻）。**前态 keys 与后态 keys 必须严格同表**（前态 NOT_ANY ↔ 后态主键），建议脚本断言一致。

### 事件双态示例（plant→payoff，放共通库）

世界级事件（如「信物之约」的约定→兑现）同样做成双态：plant 态 keys=「会自然提起该钩子的对话表面」（物件/场景词），NOT_ANY 副键=payoff 词表；payoff 态 keys=兑现说法（如「把信物交还」「约好的那个」），order+2 压制，sticky=999。**防剧透规则**：谜底词不作 plant 主键——plant 只响应「对话表面」，谜底揭晓由 payoff 词表门控。完整参数见 `examples/staged_entries_example.json` 后两条。

## 二、失效模式清单（F1-F9）

- **F1 用户绕开关键词**：交底措辞千变万化，词表覆盖不到时后态不翻、前态不退。对策三层：a) 词表覆盖正典原话句式＋常见用户变体；b) 条目级 `scan_depth` 拉大兜底（翻转变体说得早、被长对话挤出窗口时）；c) 终极兜底＝**手动点灭前态**（ST 世界书面板操作，卡文件不动，符合「卡不动」）＋对角色说一句含翻转词的追认台词重触发。
- **F2 前缀陷阱（最凶险的坑）**：ST「Include Names」默认开，扫描缓冲含每条消息的说话人前缀——**每条角色消息头部都天然含角色名及其子串**。角色名（或其任何子串）一旦进任何 selective 条目的 keys，该条目永活。故全组键表禁用角色名及其子串的单独形式；用户人设名/群成员名含键词同理危险。
- **F3 问句碰撞**：裸关键词（如「真名」）不作翻转键——「你的真名是什么」是化名态的正当触发场景，若其为后态键，一问即假翻转。翻转键全部取**第一人称陈述句式**。进阶方案：ST 键原生支持正则，可写否定前瞻（如 `真名(?!.{0,4}(什么|啥|多少))`）排问句，属可选增强，默认不用（可读性差、调试难）。
- **F4 状态回退（sticky 到期）**：后态 sticky=999 条消息后，若期间无人再说翻转词且话题离开，后态失活、前态复活——玩家感知即「角色突然又不认账了」。概率极低（999 条≈超长团），且后态 keys 的追认句会自然复现刷新 sticky。量产期建议实测回退临界点。
- **F5 剧透快进**：玩家在剧情前主动喊出翻转词（读过原作）→ 状态被提前翻转。判定：**接受**——用户主动剧透＝玩家选择快进；要硬防可加严键表，但不建议（牺牲召回）。
- **F6 兑现分叉**：若正典中事件分两步兑现（和解线/交付线），payoff 词表把两步合为一门——玩家只走一步，状态仍整门翻转。可接受（事件在正典中本是一约两付）；精细版可拆两对双态，token 成本翻倍，按需取舍。
- **F7 常用词误压**：前态键若是生产/日常技能词，无关剧情会误触。误触代价低（浮旧忆，不违和）可保留；噪声大则收窄键表＋vectorized 语义兜底。
- **F8 与手动条目分层**：若有手动启用的「终局锚」条目与自动双态并存，建议手动条目启用时机放在 payoff 翻转之后（正典顺序亦然）；可给手动条目的 NOT_ANY 加 payoff 词避免谜态并存。
- **F9 推测态的过度自信**：payoff 是创作层外推时，模型会把「八九不离十」演成「确证」，抢跑正典。对策：内容内锚定「推测」措辞＋指纹保留原话自我限定；判卷按 creative 口径核查。

## 三、群聊兼容与库归属判定

**判定规则**：身份态=专属库；剧情大事件态=共通库。

1. **身份态→专属库**：真名/秘密红线是角色本人的身份状态，翻转与否只应改变该角色的行为；其他成员卡各有各的知情状态，不该被别人的交底态注入。专属书绑定角色，群聊中只对该成员生效，天然隔离。
2. **事件态→共通库**：世界级事件状态（信物交付与否、王之正体推测立与未立）对全场角色是同一事实。放共通库则所有成员卡共享同一状态判定，避免「同一房间内事实分裂」。
3. **共通库注入是房间级的**：ST 世界书激活按聊天而非按成员，共通条目命中后注入一次、全体可见——大事件态正确；但若误把身份态放共通库，该角色不在场的回合也会注入其交底态（浪费 token 且可能污染旁白）。
4. **群聊前缀陷阱放大（F2 群聊版）**：Include Names 使扫描窗含所有发言人前缀。群成员的**角色名/用户人设名**若含键词，对应状态条目会被前缀常驻误触。建群时按键表做成员名碰撞检查；中文无分词，`match_whole_words` 无效，只能改键表或移词。
5. **群聊 scan_depth 稀释**：scan_depth=4 在群聊＝全场最近 4 条，单人发言占比下降，翻转词更容易落在窗外。对策：共通库后态条目级 `scan_depth=6`，或群聊局提高全局 Scan Depth 至 6-8。
6. **递归关闭前提**：键表安全性依赖递归关闭（卡级 `recursive_scanning=false`）——条目内容中的引文（含人名/事件词）不应触发其他条目；若用户全局开递归，条目级 `prevent_recursion=true` 兜底防自触发。

## 四、与静态条目的分工

| 层 | 条目 | 性质 |
|---|---|---|
| 静态设定层 | 名称体系/世界观 | 两态通用，不参与翻转 |
| 指纹库 | 口吻/台词指纹（引文混排） | 引文语料，供风格模仿 |
| **状态机（本机制）** | 双态对 | **单态在位**，事件词驱动翻转 |

三层分工明确，互不删改。已知摩擦：指纹库若混排两态原话（交底前后的句子同条），化名态在位时会提前泄漏「已是现名」的口吻——量产建议把交底后指纹迁入后态条目。
